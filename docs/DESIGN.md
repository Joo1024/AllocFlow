# AllocFlow v0.1 设计基线

## 产品与交付

InvestmentPlan 是权威输入；固定 MarketDataset 和 RunSpec 决定一次运行。
SDK、CLI、Streamlit 只调用同一个应用服务。六个模板是 YAML 实例而非六个引擎。
美国 ETF、中国股票、场内基金和场外基金使用统一资产标识，币种、交易日历、
数量步长与执行延迟由资产规格表达。场外基金采用“延迟至确认日可见净值”的研究近似，
不声称复刻未知价申赎、交易确认与结算。真实申赎模型留给 ExecutionModel 扩展。

## 配置契约

所有业务参数是必填字段；无可选行为时明确填 null 或空列表，未知字段拒绝。
公开预设仅位于 examples/*.yaml；引擎无隐含投资金额、币种、阈值或 ticker。
模板必须显式选用，不存在自动读取某份默认策略的行为。
YAML 安全加载、重复键拒绝、完整跨字段验证。每次编辑重新验证，不使用未校验 model_copy 更新。
导出 JSON Schema、解析后完整配置和内容指纹。不同 schema_version 必须显式迁移。
参数错误定位到字段；执行失败保留原因、日期、规则和预算。

## 模型先行

- PlanSpec: 身份、区间、报告币种、日历、资产树、标签组、预算、现金流、有序规则、执行。
- InstrumentSpec: 稳定 id、provider symbol、资产类型、币种、日历、价格模式、份额步长、延迟。
- AllocationNode: 递归目标树；叶节点唯一持仓，节点相对权重逐层合计为1。
- BudgetSpec: 现金用途、币种、归属配置节点和显式现金利率；预算不是额外资产。
- CashflowSpec: 初始/一次/每月收支、增长、暂停、预算分配；提款政策单独定义。
- RuleSpec: 投资、预算上限、再平衡、扩展策略；Trigger/Selector/Sizer 显式嵌套。
- AccountState: 实体现金、唯一库存、预算余额、成本、累计外部流、基金份额与规则状态。
- PolicyContext: 不可变状态快照、当时可知信号、目标权重、规则参数。
- Intent/ExecutionEvent/Valuation/RunResult: 意图、原子提交、逐日事实与稳定投影。

模型分布在 config/、domain/；核心不得依赖 UI、provider session 或 DataFrame。
单文件目标小于300行；按职责拆分，不以截断一段逻辑的方式凑行数。

## 金融契约

1. 模拟是日级研究模型：联合各交易所 session，月末决策使用配置日历；
   信号只读严格早于执行日且 available_on 已到达的数据。执行可用当日收盘价。
   非本市场 session 的意图排队至自身下一 session；日级时间不声称还原盘中跨时区顺序。
2. 顺序：计息与开盘前估值 → 到期意图 → 外部现金流/换汇/预算分配 → YAML 顺序规则 → 收盘估值。
   每条规则看到前面规则提交后的状态。异步成交保留提交与成交日期。
3. 预算之和等于各币种实体现金；单一 instrument 只有一个权威数量。
   成交、费用、数量和预算原子提交。拒绝不改变金融状态。
4. 外部投入/提款在流前估值后按单位净值发行/赎回基金份额。
   内部换汇、预算转移、买卖不是外部流。首次手续费进入首个报告窗口。
   无资金时指标为不可计算；已归零但仍有基金份额的账户拒绝新投入，避免隐藏净值重启。
5. FX rate 表示一单位币种折合多少 dataset base_currency；交叉汇率由两边相除。
   Decimal(str(price)) 转入执行，现金精度、份额步长、固定/比例/max手续费、FX价差显式配置。
6. v0.1 仅接受显式标识的合成总回报/来源调整价格，允许碎股。
   不再另发分红；原价+公司行动模式尚未实现时直接拒绝。调整价格不能声称是真实券商库存。
7. 再平衡可使用 budget_inclusive：配置节点下受保护且未投入的预算现金按节点叶权重抵扣目标证券金额。
   股票预留资金因此占股票预算，但不算实际股票持仓。受保护预算不列入可用资金。
   或选择 holdings 口径；阈值、目标节点、资金来源和检查频率全部配置。
8. 提款先使用配置的预算，再按显式资产顺序卖出；partial/reject 控制不足行为。
   reject 使用试算状态，不能留下部分卖出。净提款以实际支付额单位化。
9. 逐期金额归因：证券本币价格效应按期末FX；FX效应按期初数量与期初价格；
   交叉项归证券效应。费用、现金利息和FX价差分别记录，剩余为显式舍入残差。
10. 日收益与月收益分开，指标显式频率。XIRR 为投资人视角且含期末残值；
    不把选中的一个根说成唯一根，搜索域、残差、非传统现金流状态均公开。
11. 固定数据包含来源、价格口径、effective date、available_on、获取时间和文件哈希。
    当天下载历史数据不等于 point-in-time 数据；available_on 的依据必须写明。
12. 情景 jointly 抽样资产/FX；共同路径比较计划；SeedSequence(root_seed,path_id)。
    资金耗尽是有效结果；计算失败单独统计，不当作破产、不静默丢弃。

## 用户样例与公开假设

用户确认的精确金额与权重写入 examples/user_plan.yaml：初始CNY100000，月入CNY10000；
初始60%股票直接买入、24%债券、16%SGOV；后续42%DCA、18%回撤、24%债券、16%SGOV。
回撤10/20/30%用当时加仓池余额的20/40/40%，仅选满足的最高档，不累计档位；
non_tech=VOO/VTV/VO/VB/VXUS；最低USD500、最多2资产；池上限为当月流入12倍；每笔USD1。

以下为待用户试用的具名模板假设，不是引擎默认值：以VOO历史可见高点衡量回撤；
每个自然月最多触发一次；按低配金额排序，平手按instrument_id；最低部署额是含手续费总预算；
初始CNY100000之外的月投入从下个月开始；月末检查绝对偏差5个百分点；再平衡使用预算口径；
机会池受保护，卖出资金进入DCA池；零现金利率、零FX价差；示例区间由YAML明确给出。
日期/阈值/规则/资产/费用均可编辑。未添加第十年大额支出。

## 扩展接口

Strategy.evaluate(PolicyContext, 参数模型) -> Intent 序列。
内置规则通过登记表分发；SDK register_strategy 注入可信 Python 子类及参数模型。
YAML custom rule 引用登记名，不任意 import、不 eval 表达式。
MarketDataset、ExecutionModel、策略、结果投影均有明确类型；更换 UI 不改变金融模型。

## 验收基准

- 平价+固定FX+无费用，任意合法流入/流出不改变单位净值。
- CNY100000按7换成USD后初始股票全额建仓；首月股票预算不形成30%机会预留。
- 后续CNY10000按7换汇分别形成USD600/257.142857…/342.857142…/228.571428…预算。
- 价格100、现金预算101、固定费1时买1份；费用扣一次。
- 价格100、比例费1%、预算101时买1份；资金不足及超额卖出原子拒绝。
- 月度最高档回撤、两标的上限、最低额、预算上限和保护资金分别验证。
- 多币种投入中性、提款不足partial/reject、日历延迟、不可见数据、归因勾稽。
- 六模板同一引擎、串行并行路径一致、导出后可复现。

## 实现补充

提款在卖出费用计入净值后赎回份额；清空账户保留最后有效净值作为下一次投入锚点。
延迟订单锁定现金或库存；延迟资产不可用于当天提款，须提前卖出。

## 比例提款与文件恢复

WithdrawalSpec.amount_basis 必填：fixed 使用现金流固定金额；portfolio_fraction 使用
fraction × 提款前账户价值。fraction 在 fixed 模式必须显式为 null；比例模式的固定金额和
annual_growth 必须为0，避免相互矛盾的输入。现金流币种只决定请求支付的币种。

运行包新增 checkpoint.json，含版本、账户契约、状态及 SHA256。load_checkpoint(path, plan)
验证报告币种、预算币种、资产币种与份额步长，再恢复Decimal、日期、订单、事件和规则状态。
续跑起点必须晚于检查点；允许显式调整后续规则，不能静默更换账户币种。
SHA256用于发现意外修改，不作为数字签名或来源认证。

自定义策略在引擎执行任何现金流或订单前检查登记名与参数模型。
